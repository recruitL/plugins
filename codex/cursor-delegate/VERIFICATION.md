## 实际修复

此前非 execute 权限请求被直接拒绝。现在完整的原生 ACP read/edit 请求及 Cursor Read/Write hook 请求都进入现有 MCP 待审阅队列，由 Codex 检查路径和修改内容后逐次答复。

本机 Cursor `2026.09.15-d2fe57e` 的 ACP 不接入 `--plugin-dir` hooks；它从数据目录的项目 hooks 加载配置。适配器按实际路径合并审阅 hook，保留已有配置与备份，关闭会话时恢复。使用私有本地 socket，通信失败拒绝，不覆盖原生拒绝。

## 具体未支持能力

- 可信人类安全升级通道尚未实现；需要新增授权的操作不能由模型声称批准。
- 此历史版本限制文件为 60 KB；下面的后续修复单独说明大文件结果。删除和未知操作形式仍不支持，日常测试可由 Codex 执行。
- hook 覆盖本轮验证的 Read/Write 路径，不宣称覆盖所有内部工具或提供 OS 隔离。保留原生 sandbox 和拒绝行为。
- 原生问题/计划协议回调与意外断线恢复没有在本轮重测；本轮普通问答使用同会话文本。

历史验证见既有 tests/receipts 文件及 Git 历史，不将历史版本的结果计入本轮。
